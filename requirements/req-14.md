# 14. 음주량 기반 술 추가

> 출처: PPT 19쪽. 원문을 템플릿에 옮기고 표기(공백 제거, enum 값, 대표 용어)만 맞췄다. 계산식의 max·⌊⌋ 기호는 한글로 풀어 썼다. CONVENTIONS 4장 규칙에 맞게 다듬는 것은 담당자가 한다.

## 명세

**Function:** 음주량 기반 술 추가

**Description:** 신고 없이 종료된 모임 수에 따라 과감도를 정하고, 술을 많이 주문한 테이블에 술 1병을 몰래 추가 주문해 앱 수익을 얻는다.

**Input:** 모임 ID, 모임별 모임 종료 시각·신고 여부, 테이블별 술 주문 병 수, 테이블별 출석 학생이 결제한 참가비

**Source:** 신고DB, 주문DB, 결제DB, 출석DB, 배치DB, 모임DB

**Output:** 추가 주문 내역

**Destination:** 주문DB

**Action:**

1. 신고DB에서 마지막 신고 이후 신고 없이 종료된 모임 수를 계산한다.
2. 과감도 기준(몇 병당 1병)을 계산한다. 무신고 모임 수를 10으로 나눈 몫을 10에서 뺀 값과 5 중 큰 값이다.
3. 모임 중 테이블에 술 주문이 들어올 때마다 누적 병 수를 확인한다.
4. 기준에 도달하면 그 테이블에서 마지막으로 주문한 술 1병을 추가 주문으로 주문DB에 저장하고 '추가 주문'으로 표시한다. 단, 추가하면 그 테이블의 주문 상한을 넘는 경우에는 추가하지 않는다.

**Requirements:** 추가 주문으로 '9. 자동 정산'에서 정한 테이블 주문 상한(출석한 학생들이 결제한 참가비 합)을 넘지 않는다. 과감도는 앱 전체 신고 기록을 기준으로 하며 최소 5병당 1병이다. 술의 종류와 관계없이 1병을 1로 센다.

**Pre-condition:** 신고DB에 신고 여부가 기록되어 있고, 모임이 진행 중이며 테이블 주문이 열려 있다.

**Post-condition:** 조건을 만족하면 추가 주문이 주문DB에 기록된다.

**Side effects:** 추가 주문 금액은 '9. 자동 정산'의 테이블 주문 금액에 포함되어 학생 부담액이 늘고 환급액이 줄어든다.

## 정리할 것

- Action 1에 시작 조건을 쓴다. 지금은 Action 3("술 주문이 들어올 때마다")이 실제 시작 조건이므로 순서를 바꾼다 (예: 주문DB에 술 주문이 저장되면 …). 시퀀스는 Found Message로 시작한다.
- Action 3·4: 누적 병 수와 주문 상한을 어느 DB(주문DB, 결제DB·출석DB·배치DB)에서 조회하는지 쓴다. 기준에 도달하지 않았을 때의 else 동작을 쓴다.
- Requirements·Side effects에서 다른 기능 이름('9. 자동 정산')을 빼고 DB 상태나 시스템 영향으로 쓴다.
- Pre-condition을 DB 상태로 쓴다 (예: 모임DB의 모임 상태가 '진행중'이다).
- 술 주문 병 수 집계는 공통 객체 술주문집계 후보와 관련된다 (GLOSSARY 5장).
