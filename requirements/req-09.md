# 9. 자동 정산

> 출처: PPT 14쪽. 원문을 템플릿에 옮기고 표기(공백 제거, enum 값, 대표 용어)만 맞췄다. CONVENTIONS 4장 규칙에 맞게 다듬는 것은 담당자가 한다.

## 명세

**Function:** 자동 정산

**Description:** 모임 종료 시각에 주문을 마감하고, 계산된 금액을 환급한다.

**Input:** 모임 ID, 테이블별 주문 금액, 출석 학생별 참가비

**Source:** 주문DB, 배치DB, 출석DB, 결제DB

**Output:** 모임 상태, 주문 마감, 환급액, 환급 알림

**Destination:** 모임DB, 주문DB, 결제DB, 학생UI

**Action:**

1. 모임 상태를 '종료'로 바꾸고 모든 테이블의 주문을 마감한다.
2. 테이블마다 테이블 주문 금액 T, 출석 학생이 결제한 참가비 합 S, 출석 인원 N을 구한다.
3. 출석 학생 1명의 환급액을 (S − T) ÷ N으로 계산한다.
4. 환급액을 결제DB에 기록해 환급하고, 학생에게 알린 뒤 '10. 만난 사람 평가' UI를 띄운다.

**Requirements:** 출석 기록이 없는 학생의 참가비는 환급하지 않는다. 원 단위 나머지는 학생 ID 순으로 1원씩 나눠 합계를 맞춘다.

**Pre-condition:** 모임 종료 시각이 되었다. 모임 종료 시각은 '1. 모임공지등록'에서 입력한다. 테이블 주문은 그 테이블 출석 학생이 결제한 참가비 합을 넘지 않게 받았다.

**Post-condition:** 결제DB에 환급액이 저장되고 환급된다.

**Side effects:** None

|---|---|---|
| 전체 | 표기 변경 | 학생 UI → 학생UI, 출석 학생 수 → 출석 인원, 종료 시각 → 모임 종료 시각 |

## 정리할 것

- Action 1에 시작 조건을 쓴다 (예: 모임 종료 시각이 되면 시스템은 …). 시퀀스는 `시간` 액터로 시작한다.
- Action 2: T, S, N을 각각 어느 DB(주문DB, 결제DB, 배치DB·출석DB)에서 조회하는지 쓴다. 출석 인원이 0인 테이블의 else 동작을 쓴다.
- Action 3: 계산식 (S − T) ÷ N을 한글로 풀어 쓴다 (예: 출석 학생이 결제한 참가비 합에서 테이블 주문 금액을 뺀 값을 출석 인원으로 나눈다).
- Action 4의 "'10. 만난 사람 평가' UI를 띄운다"는 다른 기능을 실행하는 표현이다. 모임DB의 '종료' 상태나 결제DB의 환급 기록까지만 쓰고, 10번이 그 상태를 시작 조건으로 보게 한다.
- Pre-condition에서 다른 기능 이름을 빼고 DB 상태로 쓴다. Side effects를 쓴다 (환급 알림 푸시, 결제DB 기록 증가 등).
